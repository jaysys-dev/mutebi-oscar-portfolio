## Session goal

Bring the Mutebi Oscar portfolio project onto the JaySys web application standard, without
changing the website itself.

Three phases in one session:

1. Audit the project as it actually stood.
2. Produce a migration plan and get it approved.
3. Execute the reorganization and validate it.

## Work completed

### Phase 1 — Audit

Inspected all 68 files in the project root: HTML, CSS, JS, Markdown, JSON, YAML.

What the audit actually found, including things I had not expected:

- The root held **two separate products** — the 5-page portfolio site and a 58-file,
  20-screen `community-operations-platform/` prototype with its own design system, README
  and CI. The root `README.md` never mentioned the second one.
- **No git repository anywhere.** All work to date was unversioned.
- **No `index.html` at the root** — serving the root produced a directory listing.
- **Zero asset files in the entire project.** 20 empty asset directories; all 80 images
  hot-linked from Unsplash, 3 videos from YouTube, fonts from Google.
- All 25 pages had **zero broken internal links**. The existing structure was sound, just
  non-standard.
- The root `README.md` **contradicted itself** — the structure block called four pages
  "Structure only" while the status table marked all five complete.

### Phase 2 — Migration plan

The most useful thing done this session was **measuring the migration before executing it**.

Counted every relative reference in the five pages: **113 total**. Then worked out which
would actually break. Because every internal link used the up-and-back-down form
(`../about/about.html`), moving all five page folders into `pages/` together preserved their
relative distance to one another — so **only 29 references needed to change**, in three
find-and-replace patterns.

That reframed the whole job from "risky restructure" to "three replacements plus a lot of
documentation writing."

Five decisions (D1–D5) were raised, recommended, and approved before execution.

## Important decisions made

| # | Decision | Why |
| --- | --- | --- |
| D1 | Leave `community-operations-platform/` untouched | Separate product. Forcing it into `pages/` would have collided `pages/media/` with its `media.html` and merged two independent design systems. |
| D2 | Add a root `index.html` | The approved target tree had no root file, so migrating "successfully" would have left the audit's top finding unfixed. Flagged as an addition. |
| D3 | Keep the `home/index.html` vs `about/about.html` inconsistency | Following the approved structure. Normalising the other four would have added 84 more edits for zero functional gain. Recorded rather than silently "fixed". |
| D4 | `components/` = reference copies, not includes | There is no build step. Files there change nothing at runtime. Said so explicitly in `components/README.md` rather than leaving a trap. |
| D5 | Fresh root `.github/` | The prototype's `ci.yml` runs `npm ci` against directories with no `package.json` and would fail. Promoting it to root would have created a permanently red CI. |
| — | Structure-only migration | Deliberately did **not** fix the legacy `theme-color`, dead `initActiveNav()`, or hex-literal leakage, so any regression would be attributable to the move alone. |

## New concepts and commands practised

**`git mv` for rename tracking.** Using `git mv` rather than moving files in the shell meant
git recorded all five moves as renames (`R`), so `git log --follow` still traces
`pages/home/index.html` back through its life as `homepage/home.html`.

**Checksum-gated migration.** Recording SHA-256 of `style.css` and `main.js` before the move
and re-verifying after turned "I didn't touch those files" from an assertion into a proof.

**Failure-signature assertions.** Rather than only checking the intended result, I asserted
the *specific failure mode*: `../home/home.html` must appear **0** times. That is what a
half-applied rename produces, and it 404s silently on every page's brand link.

Per STANDARD 008, the environment-equivalent commands for the core operations:

| Operation | Bash | PowerShell (used) | Python |
| --- | --- | --- | --- |
| Move + track rename | `git mv a b` | `git mv a b` | `subprocess.run(["git","mv",a,b])` |
| Recursive file list | `find . -type f` | `Get-ChildItem -Recurse -File` | `pathlib.Path('.').rglob('*')` |
| Count matches in files | `grep -ro 'pat' \| wc -l` | `[regex]::Matches($t,'pat').Count` | `len(re.findall(r'pat', t))` |
| SHA-256 of a file | `sha256sum f` | `Get-FileHash f -Algorithm SHA256` | `hashlib.sha256(open(f,'rb').read()).hexdigest()` |
| Remove empty dir tree | `rmdir -p d` | `Remove-Item -Recurse -Force d` | `shutil.rmtree(d)` |
| Serve a folder | `python -m http.server 8000` | `node serve.js` | `python -m http.server 8000` |

PowerShell was the working environment this session (Windows 11 host).

## Problems encountered and how they were resolved

**1. The live HTTP validation failed on first attempt.** All eight targets reported
"connection actively refused". The obvious conclusion was that the sandbox blocked network
binding — which would have meant abandoning live validation.

Rather than accept that, I ran a minimal bind probe. It printed `LISTENING`. So the port was
fine and the real cause was that `Start-Process node -ArgumentList @("-e", "<long script>")`
mangled the inline script through PowerShell's argument parsing. Writing the server to a file
and passing the path fixed it, and all eight targets returned 200.

Worth remembering: *"the environment won't let me"* is a conclusion that deserves a
30-second probe before it is believed.

**2. Broken markdown tables in the generated page-copy docs.** Each page's `<title>` contains
a pipe character (`Community Desk — Owebyenkulakulana | Contact & Requests`), which split the
table cell. Fixed by escaping pipes to `\|` in the title and description rows.

**3. Components would have failed link validation.** The extracted header/footer partials
contain paths written for a page at `pages/<route>/`, so they cannot resolve from
`components/navigation/`. My first validator scanned `components/` and would have reported
false failures forever. Scoped the validator to `pages/` + root `index.html` and documented
why in both the script and `components/README.md`.

**4. Header and footer were not byte-identical across pages**, as I had assumed when planning
the component extraction. Diffing showed the differences were all intentional — the
active-link marker moves per page, Community Desk points its CTA at an in-page anchor, and
Projects uses in-page anchors for its own pillar sections. Documented the variations in the
partials rather than pretending a single canonical version existed.
